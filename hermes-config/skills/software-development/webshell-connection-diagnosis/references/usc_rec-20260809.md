- 80B 小密文 × 错误密钥(补零 Aa12345600000000) 也报 "Bad IL format"
  → PKCS7 偶发通过陷阱实证：固定小明文测密钥不可靠，必须用真实 DLL 复测

- 单 IP 208.98.35.167，重复 GET 错误页源码一致 = 无多 worker/轮询
- 服务器响应始终无 Set-Cookie（会话未写入时不发 cookie 属正常，勿据此判会话坏）

## 冰蝎客户端 jar 内部（Behinder_v4.0.6/Behinder.jar，Java8 javap 可看）
- core/Crypt.class：同时存在 AES/ECB/PKCS5Padding 与 AES/CBC/PKCS5Padding 两套；
  默认路径（ENCRYPT_TYPE_AES）= CBC；另有 native(JNI) 加密
- core/ShellService.getCryptor(int)：CustomCryptor(自定义传输协议) / LegacyCryptor(默认,
  transProtocolId=-1)；aspx 请求 Content-Type: application/octet-stream（裸 body）
- data.db（SQLite，Behinder 目录下）：
  - shells 表: id,url,ip,password,type,os,comment,memo,addtime,updatetime,accesstime,
    headers,catagory,status,memType,transProtocolId,config
  - proxys 表: id,name,type,ip,port,username,password,status（4.0.6 默认 127.0.0.1:1080
    neoreg；4.1 默认 127.0.0.1:7890 Clash）
  - TransProtocol 表: id=28 'default_aes' type=aspx = **ECB + base64**（陷阱协议，与标准
    马 CBC+raw 不兼容，选了必解密失败）；负 id 为内置协议
- payload/csharp/*.dll（Cmd.dll 9216B、BasicInfo.dll 10752B 等）: 直接是合法 .NET 程序集
  （MZ+PE+CLR 头齐全），功能载荷，9KB+
- Constants.class 内嵌 C# 模板（class E / class AES）用于自定义协议生成

## .NET RijndaelManaged 报错真值（本机 csc.exe 实测，中文 locale）
| 场景 | 报错 |
|------|------|
| 空密钥 + 空数据 | IV 长度与算法密钥大小不匹配 |
| 16B 密钥 + 空数据 | 数据无效无法移除填充 (Padding is invalid) |
| 16B 密钥 + 15B 数据 | 要解密的数据的长度无效 |
| 16B 密钥 + 16B 全零 | 数据无效无法移除填充 |
| 错误密钥 + 合法长度密文 | 数据无效无法移除填充 |
