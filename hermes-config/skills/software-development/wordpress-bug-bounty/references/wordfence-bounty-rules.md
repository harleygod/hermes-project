# Wordfence Bug Bounty 规则要点(2026-08 会话整理)

## 收录范围
- 安装量 < 1000 的插件/主题:**只要在 wordpress.org 仓库中就在范围内**(免费插件 0 安装也可提交)
- premium 插件/主题(不在仓库):安装量 ≥ 1000 才 in-scope;按销售额 1:1 折算安装量
- 有免费版的插件:免费版安装量在范围内则 premium 版也视为 in-scope,赏金按 premium 安装量计

## 赏金档位(公开规律,非官方表)
| 安装量 | 一个有效漏洞赏金 |
|--------|------------------|
| 0-100 | $5-25(最低线,破零用) |
| 100-1,000 | $25-100 |
| 1,000-10,000 | $100-500 |
| 10,000-100,000 | $300-1,500 |
| 100,000-1,000,000 | $500-3,000 |
| 1,000,000+ | $1,000-10,000(未认证 RCE 顶级) |

## 扣钱/降级因素
- 利用需要特定软件设置或服务器配置(如"表单勾选某选项")→ AC 上调,严重度下调
- 需要用户交互(点链接等)→ 降级
- **依赖同一软件之外的另一个漏洞 → 赏金至少减半**(链必须全在同一插件内)
- 影响面小(只能读邮箱/路径)→ Basic Information Disclosure 低值 $5-25
- 重复/已公开披露 → $0

## 高价值类型(High-Threat)
未认证 RCE(任意文件上传/SQLi/反序列化/PHP 对象注入)、未认证/低权限→管理员提权、任意文件删除/读取/写入、SQL 注入、认证绕过、高敏感信息泄露(数据库凭据/API key/密码)。
- PHP Object Injection:有**新文档化可用 gadget** 才最高级;否则低值
- 提权后能装插件 = RCE 前置(Wordfence 视为完整链)

## 1337 Wordfence Vulnerability Researcher 身份
- 累计有效提交达到门槛后获得;获得后**所有后续提交自动享受 bonus**
- 所以第一目标是破零(哪怕小洞)
