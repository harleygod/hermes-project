# 影响范围调查方法论（0 命中时怎么判）

来源：泛微 e-cology /dispatch/invoke 0day 影响范围调查（2026-08，~300 目标 0 命中）。

## 触发场景
拿到一个新洞/0day 入口，先只读扫一批资产看影响范围，结果 0 命中（或极低命中）。

## 0 命中判定流程（四步，缺一不可）
1. **随机路径对照**：先 GET 一个随机不存在路径，确认目标是不是"全 200 软404"服务器——软404 会把存在性判断全搞废
2. **方法/路径变体**：抽查 1 个目标，变体覆盖 GET/POST、短路径（/x/）、带上下文前缀（/ctx/x/）——全 404 才信"入口不存在"
3. **WAF 排除**：若部分目标带保护层指纹（如 Server: WVS 等非典型头），找同批**裸部署**（正常 Server 头）目标对照——裸部署也 404 = 不是 WAF 吞的
4. **版本细分样本**：0 命中但样本版本同质时，结论只覆盖该版本线。补其他版本指纹（如 e-cology 10 的 ecology10/10.00. 标记）再捞一批

## 阳性对照（决定性问题）
- 源头给的**成功样例 URL / 完整请求包 / 验证版本号** = 校准探测姿势的唯一钥匙
- 无阳性对照时：探测姿势对错无法区分 → 结论只能写"公网影响面≈0（未验证）"，源头"影响范围广"说辞存疑
- 问源头一句话："验证环境什么版本？"——版本号能直接锁定目标版本线，比盲扫快得多

## 样本偏斜识别
- 同组织多子域（一家 12 个子域全同端口）= 实际就 1 个部署，别按条数算影响面
- 多目标根页 ETag 相同 + Last-Modified 不同 = 同一产品模板页不同安装时间（正常，非蜜罐）；ETag 和 Last-Modified 都相同才是模板/蜜罐信号
- 版本指纹别只标"9/10"——抓 SPA 内容里的版本标记（ecology9/ecology10/9.00./10.00. 等）细分，否则版本相关性看不出来

## 探测姿势的正确性自检（本案例踩过的坑）
- URL 带 fragment（#/...）没剥 → 探测打到错误路径 → 假阳性（200 其实是登录页/SPA 页）
- 状态码 200 + 错误页内容（"您所请求的网页不存在"/404.png）= 软404，不等于存在
- 记录响应体片段（前 120 字符）供人工核对，别只信状态码
