# 金管局网络安全检查报告模板（Word 格式）

适用于金融监管机构安全检查交付（如"8.3-金管局复测"类项目）。用户提供样例 docx 后按此结构填充。

## 文档结构

```
<title> 太平洋XX网络安全检查报告
<date> 2026年X月
（2026年X月X日）

一、检查情况汇总
本次安全检查共发现漏洞N个，其中包括严重漏洞X个、高危漏洞Y个、中危漏洞Z个、低危漏洞W个。

二、本次检查情况概述
表格：序号 | 单位名称 | 系统名称 | 漏洞名称 | 漏洞危害程度

三、本次检查情况详述
3.1 <单位名称>
3.1.1 <系统名> <漏洞名称>
  系统名称 | <系统名>
  系统地址 | <完整URL>
  漏洞名称 | <域名> <漏洞类型>
  漏洞危害 | <危害描述：谁可做什么、造成什么后果，2-3句>
  危害程度 | 高危/中危/低危
  测试过程：
    【测试目的】验证XXX
    【操作】匿名GET/POST XXX
    【输入】<完整请求URL>
    【实际结果】<返回状态码+响应内容摘要>
    【判定】<漏洞成立结论>
  关键证据：
    • <具体请求与响应证据，含状态码与关键字段>
    • <第二条证据>
  整改建议：
    1、<建议>
    2、<建议>
```

## 填写要点

- 危害程度定级参考：能造成数据泄露/未授权写/拒绝服务 → 高危；信息泄露/未授权读 → 中危；指纹/配置泄露 → 低危
- 每条漏洞的"测试过程"必须可复现：输入给完整 URL（含参数），实际结果给 HTTP 状态码 + 响应关键内容
- 证据给具体请求与响应片段（如 `GET /xxx → 200 {"code":"000000",...}`），图片由用户自己截图补
- 单位名称用全称（如"中国太平洋财产保险股份有限公司"）
- 模板本身含整改建议栏目——即使平时渗透报告不写修复建议，金管局模板此栏必填

## docx 生成（docx-js）

```bash
npm install docx --legacy-peer-deps   # 一次
node gen_report.js
```

- 正文：宋体 SimSun、size 24（12pt）；标题：黑体 SimHei、bold
- 表格：`width: {size: 100, type: WidthType.PERCENTAGE}`，每格 `width: {size: 20, type: WidthType.PERCENTAGE}`
- 生成后验证：python 读 docx（zipfile）检查 word/document.xml 包含关键标题 + `zipfile.testzip()` 校验结构
